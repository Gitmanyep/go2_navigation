# P0 数据审计与 P1 真实滚动局部地图

本入口位于 `perception/`，用于机载 ROS Noetic 的真实 Point-LIO 数据。复用 `simulation/` 中的 TerrainMap 算法，但独立接入和发布，不调用导航规划器，不输出速度，不导入 Unitree SDK，不启动原雷达驱动或 Point-LIO。仿真原件、原厂 SDK、手动面板和 `backup/` 不修改。

当前已完成软件接入、离线合成场景和假 ROS 消息测试。**机载未连接，真实 ROS 运行、安装尺寸、外参、源时钟同步和移动对应关系均待现场验证。** 所有报告的 hardware_acceptance 保持 pending；配置里的 true 只是操作者声明，不是自动验收证书。

## 连接后先做 P0

在 NoMachine 的机载终端，先确认没有正在执行的本仓库短动作，检查工作区，再快进更新：

```bash
cd /home/unitree/go2_navigation_github
git status --short
git pull --ff-only
./bin/go2-nav data-audit --seconds 30
```

若 `git status` 有修改，先保留或提交，不使用 `reset --hard` 覆盖。仓库更新不会自动更新正在运行的旧程序。新命令需要 `/opt/ros/noetic/setup.bash`，由入口加载；在只有 ROS 2 Humble 的笔记本上不能直接启动这两个 ROS 1 实机入口。

需要原来的 roscore、雷达驱动和 Point-LIO 已经运行。程序只订阅：

- 点云 `/cloud_registered`：已经注册在固定世界坐标系的 PointCloud2。
- 位姿 `/aft_mapped_to_init`：Odometry。
- 方向 `/go2/navigation/direction`：带采集时间、frame_id、source_id、session_id、seq、kind=direction、valid、confidence、vector 的 JSON String。
- `/tf`、`/tf_static`：记录可见 TF 边，不发布或修改 TF，也不凭边名称认定外参正确。
- IMU 默认未配置；查明真实话题后，在本地设置文件的 `topics.imu` 填入对应名称。未配置不代表 IMU 验证通过。

终端每秒输出状态。`LOG` 目录中的 `perception/` 保存：

| 文件 | 内容 |
|---|---|
| `settings.json`、`calibration.json`、`metadata.json` | 本次参数、标定声明、来源与校验值 |
| `inputs.csv` | 实际处理的消息时间、帧名、接收时间、处理结果及拒绝原因，不保存整帧原始点云 |
| `status.jsonl` | 约每秒诊断：回调接收频率、处理频率、接收年龄、时间差、队列丢弃、TF 边、XYZ 来源 |
| `report.json` | 结束时的诊断快照与待验收状态 |

回调频率在应用队列丢弃之前统计，仍是本节点看到的 ROS 交付频率，不是传感器硬件频率证明。`source_age_p95_s` 是 ROS 接收时钟相对源时间的差，含传输／计算延迟及可能的时钟偏差，不能单凭这个数算出时钟偏移。点云—位姿的时间差统计也不证明 Livox—IMU 同步或去畸变已经正确。

`data-audit` 只发布 `/go2/perception/audit/status`，不建图。可同时录 rosbag 留下原始证据；先按实际话题确认名称，再在仓库根目录录制，例如：

```bash
mkdir -p local
source /opt/ros/noetic/setup.bash
timeout --signal=INT 30s rosbag record -O local/p0_stationary.bag /cloud_registered /aft_mapped_to_init /tf /tf_static /go2/navigation/direction
```

超时结束的退出码 124 是 timeout 的结果，不代表 bag 损坏；确认 `.active` 已结束再使用。IMU 等原始雷达话题需在确认名称后加入。此命令不启动运动，原始包保留本地，不上传 Git。

## 外参和几何的测量记录

复制未标定模板到被 Git 忽略的本地目录：

```bash
mkdir -p local
cp config/calibration.template.json local/calibration.json
```

不要为让地图出图而把标志改成 true。先记录测量日期、安装照片／示意、坐标原点、轴向、单位和测量方法，再填：

| 字段 | 需要确认的含义 |
|---|---|
| `reference_frame` | Point-LIO 输出位姿实际对应的参考点；与 Odometry.child_frame_id 核对。名叫 body 也可能是雷达 IMU，不是 Go2 机身 |
| `lidar_position_body_m` | 上述参考点在 Go2 机身坐标里的位置，单位米 |
| `lidar_rotation_body` | 从上述参考系旋转到 Go2 机身的 3×3 正交旋转矩阵，右手系，行列式 +1 |
| `body_reference_height_m` | 选定机身原点站立时到地面的高度，不是雷达高度 |
| `geometry_boxes` | 测量后的机身、头架和传感器包络，minimum/maximum 均在机身系，以米计 |
| `measurement_record` | 测量记录文件名或说明，保留原始证据 |
| `self_filter_boxes` | 只有实际实体部件的测量范围；空心头架不能用整个包络做自滤 |
| `mic_rotation_body` | 队友若给 mic_array 系方向，需要测量麦克风坐标到机身坐标的旋转矩阵 |

约定 `p_body = R_body_reference @ p_reference + t_body_reference`。对应的是实际里程计参考系，不能把 Livox 外壳原点、内部 IMU 原点和 Go2 机身原点混用。机身 XYZ 定义 x 前、y 左、z 上。确认测量与坐标关系后才声明 `lidar_extrinsics_calibrated` 和 `geometry_calibrated`；还需要静态及移动数据进一步核实，软件不会替你完成实物标定。

队友方向消息的 `frame_id` 和真实更新频率需独立确认：复制 `config/perception.json` 为 `local/perception.json`，填写 `direction.expected_frame`、`direction.expected_hz`，并按实际修改 fixed_frame、topics 和 calibration_file。配置文件里的相对 calibration_file 相对于该配置文件目录解析；也可用命令行 `--calibration` 指定。方向输入不是建图前提，缺少它不阻止 P1 建图。

## 启动 P1

```bash
./bin/go2-nav mapping --calibration local/calibration.json
```

若使用自定义设置：

```bash
./bin/go2-nav mapping --config local/perception.json --calibration local/calibration.json
```

缺少测量记录、标定声明、合法外参、几何或参考帧时，会输出 `calibration_blocked` 及具体缺项，地图保持未知。这是预期行为。默认模板故意不能直接生成可信地图。

数据处理：

1. 先检验源时间、重复／乱序、固定帧、位姿和有限点数；无效点计数后剔除，全无效或点数超限拒绝整帧。
2. 按点云源时间找位姿，优先使用前后位姿的平移与四元数插值，没有双边支持时只在最大时间差内使用最近位姿。默认时间差上限 0.05s，是软件门槛，不是硬件标定结果，不自动放宽。
3. 将雷达参考位姿换算成 Go2 机身位姿。`/cloud_registered` 已经是世界系，不能再给点云乘一次外参。
4. 滚动地图随配对机身位置移动，新进入区域初始化未知；未观测区域不因“没有回波”而清为空闲。
5. 保留有限时间的三维障碍证据及已观测高程，过期按未知处理。仅用已测实体部件进行可选机身自滤。
6. 独立发布循环监视源数据和工作线程年龄。超时后栅格全未知、高程／障碍点云为空，消息保留原始观测源时间，不能把发布时刻伪装成新观测。

| 输出 | 类型 | 含义 |
|---|---|---|
| `/go2/perception/map` | OccupancyGrid | 未知 -1、可通行预览 0、障碍／不支持地形 100 |
| `/go2/perception/elevation` | PointCloud2 | 仅已知格子的高程中心点，未知不补假地面 |
| `/go2/perception/obstacles` | PointCloud2 | 保留真实三维高度的障碍回波证据 |
| `/go2/perception/body_pose` | PoseStamped | 使用测量外参换算的机身位姿 |
| `/go2/perception/status` | String JSON | 时间、坐标、地图有效性及未验收事项 |

这些输出不能直接当成运动许可。状态里的 map_data_valid 只代表本次软件输入和时效条件满足，不是物理安全、避障或坡道能力证明。位姿参考帧改变、明显跳变或 ROS 时钟回退会清掉旧地图并要求重启入口，避免把两段地图误拼接。日志会记录原因，不自动改原厂程序。

## RViz 与验收

在另一个机载终端启动：

```bash
rviz -d /home/unitree/go2_navigation_github/config/perception.rviz
```

Fixed Frame 默认 camera_init，需要和实际固定帧一致。原始已注册点云、已知高程、三维障碍和机身位姿分开显示，显示衰减为 0，避免视觉积累掩盖真实断流。若已把工程加入 catkin，也可以使用 `roslaunch go2_navigation perception_preview.launch calibration:=/绝对路径/calibration.json rviz:=true`；直接 bin 入口不要求重编原工作空间。

验收顺序：

- 静止：地面高度、前后左右、近处物体、头架／机身回波与实物对应；记录时间差、接收频率和标定来源。
- 获准移动后低速直行与原地转向：固定墙面不随机器人移动、不明显重影，机身位姿与现实方向一致，滚动地图正确迁移，边缘新区域保持未知。使用原厂方式或已验证手动入口，建图程序不发运动。
- 安全停止后进行断流回放：地图过期后变未知，不保留“看似新鲜”的旧点云；回放重启／时间回退需要重启本入口。
- 记录实际误差和通过门槛，不把“RViz 能显示”当作完成标定；阈值需按任务精度及实测噪声确定。
