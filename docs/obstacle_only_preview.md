# 仅障碍物的实物路径预览

这一入口接入已运行的原生体素和里程计，在声明的平整测试区内计算二维绕障路线；不拟合地面、不计算坡度、台阶、粗糙度或落脚支撑。只发布专用预览话题，不发送运动指令、cmd_vel或控制模式切换，不启动或重启原厂雷达、SLAM或体素服务。

## 启动与使用

在机载仓库终端运行：

```bash
./bin/go2-obstacle-preview
```

应先保持当前原生体素显示入口运行。本入口默认订阅 `/go2/native/voxel_decoded` 和 `/go2/native/odom`；若成功显示的体素来自其他ROS点云话题，修改 `config/native_obstacle_plan.json` 中 topics.cloud，并核对世界坐标帧和体素尺寸。本入口不从Marker图形反推点云，不自动接入背部Livox或Point-LIO。

1. 在新RViz里点 **Publish Point**，点击一个真实地板体素/点。它仅记录一个固定地板Z基准，同时以当前机器狗XY位置为中心声明半径4米的平地测试区。必须确认该区是连续平地；这不是自动识别可走地面。
2. 点 **2D Nav Goal**，在测试区内选择目标。该工具发布到独占的 `/go2/obstacle_preview/goal_input`，仅本预览订阅，不发布到标准运动导航目标话题，也不启动move_base/Nav2。地板工具同样使用专用的 `/go2/obstacle_preview/floor_input`。
3. 青色线是计算出的路径，黄色球是目标；深蓝灰色表示“假设平地、未检出碰撞”，红色表示保守碰撞范围或边界间距不足。蓝灰色不是实测空闲或可通行认证。
4. 已有数字方向窗口也可通过 `/go2/navigation/direction` 输入方向：8前、7左前、9右前、4左、6右、1左后、2后、3右后；5/失焦清除方向。此模式仅接受水平body方向，不解释XYZ的竖直分量。
5. Ctrl+C只结束本入口创建的预览和RViz，不停止已有原生体素服务。

无窗口限时检查：`./bin/go2-obstacle-preview --no-rviz --seconds 15`。仍需先用配置 floor_z_m 或点击地板指定固定基准，否则保持等待。

## 本阶段的碰撞定义

地板本身不能当墙，因此仍保留**固定地板剔除带**；地板附近的极低矮物体、坑洞、台阶和坡面尚未验收。体素位于固定地板以上、默认0.75米机身/头架高度范围内时，投影到XY网格；更高的顶棚不自动投影为墙。这里的高度仅用于机身净空裁切，不构建地形高程图。

默认0.45米圆形碰撞包络、0.05米额外间距，再加体素及网格离散误差。它是围绕native base_link的暂定保守尺寸，不是实物外参标定。细长机身、头架与真实base_link参考点需后续测量验收；当前不允许接入运动执行器。

规划区之外保持未知。占据体素接口不提供完整自由空间证明，因此区内未占用单元仅是**人为平地测试假设**，状态始终输出 free_space_verified=false、traversability_suitable_for_control=false、motion_commands_sent=0。

观测过的障碍不会因为后续帧缺点就自动消失。需要重新声明地板/测试区或重启才能清除本轮障碍记忆；重置后必须收到新体素帧才允许再次出路径。新增障碍会重新规划，无路、数据过期、坐标错误或定位跳变会清空路径和候选速度。

## 输出及记录

`/go2/obstacle_preview/path`、`candidate_velocity`、`map`、`goal`、`label`、`status` 全部属于预览。candidate_velocity只表达计算建议，不是控制命令。

每次 `logs/obstacle_only_时间/` 保存来源、Git提交、代码/配置SHA256、子进程命令、配置、输入操作和状态日志。保留此前完整地形模式，本入口不改变它的阈值或验收标志。
